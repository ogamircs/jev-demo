How Jev decides

Jev is a model that never writes text. You give it some state and a set of typed questions. It gives back typed answers, each with a probability. This page puts it to work on one support desk, and gives an OpenAI model the same job, so you can see what differs.

What goes in, what comes out

A ticket arrives at Ledgerly, a made-up invoicing service. The software needs three things from it: which team should take it, how upset the customer is, and whether they want money back. Each question declares its type, so the answer can only be a value you allowed.

      More questions, same wait?
      
      
      TypeSafe says the questions in one call are answered in parallel, so asking more should not take longer. We asked 1, 3, 6 and 12 questions about one ticket. For OpenAI we tried it two ways: everything in one call, and one call per question fired at the same moment.

      Knowing when it doesn't know
      
      
      A label tells your code what to do. A confidence number tells it whether to act. Jev reports confidence from the spread of its probabilities. The OpenAI model was asked to write a confidence number next to its answer. Move the thresholds and watch 14 tickets fall into three piles.

      When not to use Jev
      
      
      TypeSafe lists counting, date arithmetic and sums as things Jev is unreliable at, and says to do them in code. We asked anyway, and gave the OpenAI model the same questions. The right answer in each case comes from a line of code.
      
    
      
    
      
    
      
    
      

    
      How the two fit together
      
    
      Jev cannot write a reply, plan a fix, or add up charges. The pattern TypeSafe recommends keeps code in charge: Jev makes the quick typed calls, code does the arithmetic and the branching, and a language model is called only when words are needed.
